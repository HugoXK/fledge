The next-step decision on a finished verify or review job is now accepted from the same role the job page uses to draw the form, and the route no longer reads `repo.repo_role`. A repository connected before its upstream access was checked keeps that column NULL, so its owner was shown the decision form and had the write refused with "choose your role first". The shared write guard is the route's only refusal now: it answers "not found" for a non-member and "a viewer cannot change this repository" for a viewer, so the page and the write ask one question.
