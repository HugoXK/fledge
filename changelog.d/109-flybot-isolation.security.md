A per-repository FlyBot container now starts with a read-only root, a single writable tmpfs at `/tmp`, every Linux capability dropped, `no-new-privileges`, a non-root user and the existing CPU, memory and PID ceilings, and the host Docker socket is never mounted into it. A new isolation check starts a throwaway container with exactly those arguments and asserts each fact from inside it — the root refuses a write, the effective capability set is empty, a seccomp filter is loaded, the socket is absent, only the repository's own data directory is a host bind, and a container on another tenant's network is unreachable — and exits 3 where no Docker daemon exists instead of reporting a pass. Egress is unchanged in this slice.
