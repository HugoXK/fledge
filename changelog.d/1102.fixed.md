The GitHub App repository picker no longer answers a listing that failed with the empty-installation sentence. When `/repos/new?installation=<id>` cannot read the repositories it now says the list could not be read, keeps GitHub's reason and offers `重试` / `Retry` on the same URL; a genuinely empty installation keeps its sentence and gains a `授权更多仓库` / `Grant more repositories` link to the App's installation settings, drawn only when the App has a slug.
