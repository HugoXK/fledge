Repository and user budgets now sit beside the per-job budget: a maintainer can cap a repository's rolling 30-day spend or one person's spend across repositories, each with alert, pause or cancel. Every scope reads the same single checkpoint, the refusal names the cap that fired, precedence runs job → repository → user, and the repository page shows each scope's cap, its spend and a lower-bound caveat when a call could not be priced. Clearing a cap to zero deletes it, and the account purge deletes the scopes that name the account and reports them in its retention row.
