Destructive actions now ask for a fresh GitHub confirmation: deleting a repository, toggling auto-merge, changing a quota, creating or revoking an API token, approving or rejecting a user, and stopping a FlyBot instance are refused when the session has not re-authenticated within `RECENT_AUTH_MINUTES` (default 15). The refusal is audited as `recent_auth_required`, GitHub is asked to confirm the account again, and the form returns with its CSRF token intact so the action can be submitted once. Reads and normal job actions are unchanged.
