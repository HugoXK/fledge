A connected repository can now be given a version tag from its Fledge page: enter a SemVer version and confirm the full commit SHA, and Fledge checks that there is something new to release, that the version is higher than the previous tag, that the tag does not already exist, that the confirmed SHA is a commit in the repository, and that the repository has a gate and a tag-triggered release workflow before it creates an annotated tag with the token it already holds for the repository (the GitHub App installation token when installed, otherwise the connected account's repo-scoped token). A refusal names the reason and the next legal version on the page itself, and a tag is never moved or deleted; Fledge still leaves the GitHub Release draft and its publication to a person.
