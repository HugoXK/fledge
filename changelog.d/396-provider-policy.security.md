Repositories can now restrict model use to an allowlist of their providers and an optional region, with the gateway refusing a disallowed model or fallback by a stable code before any upstream call, and refusing a call that names no model of the repository (`FLEDGE_PROVIDER_POLICY_NO_MODEL`) so omitting the field cannot skip the policy; job records and review surfaces name the provider, region and model and keep them when a later call resolves no provider, and provider metadata adds a data-policy link and an allowed flag, with a disabled provider no longer selectable as an allowlist entry, without writing keys or credential-bearing URLs to logs or audit.
