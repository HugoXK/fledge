A person can now start a triage job from the repository page: the new control sits beside the run and plan starts, is available to a maintainer or a developer (not only an admin), and opens no branch or pull request. It accepts one optional issue URL that focuses the board; a link from another host or another repository is refused with a visible error and no job is queued, because the route binds the link to the repository before it enqueues rather than leaving it to the callback. Leaving the field empty reads every open issue and pull request. A start while the repository already has a queued or running job is refused with the existing "this repository already has a job running" message, and the job page shows the triage work-type contract plus "No triage result yet" until the report lands.
