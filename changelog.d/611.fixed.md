Every enqueue refusal now renders as one bilingual sentence in the console banner. The twelve refusals that previously fell back to the service's Chinese text, or to a bare parameter such as a work-type token, have a sentence in both languages; a triage kind/work-type mismatch is now its own `WORK_TYPE_MISMATCH` refusal. `INSTANCE_NOT_READY` and `PREFLIGHT_FAILED` no longer put an upstream exception's host, port, error class or status into the redirect or the banner; that text stays in the audit row. Every enqueue refusal code is now a closed, type-checked set, so a new refusal cannot ship without both sentences.
