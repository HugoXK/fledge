A release tag created from a repository's Fledge page now gets its workflow run tracked. Fledge reads the bounded run and job list for the tag, records the run id, attempt, status and conclusion, and prepares one draft GitHub Release only when the run finished successfully and every job was success, neutral or skipped. A failed, cancelled or timed-out run is recorded as failed and is never rerun; an existing Release for the tag is marked external and never duplicated. A maintainer can re-check the run from the repository page, and publishing the draft stays a human action.
