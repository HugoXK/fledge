Who may press merge is now the role the person holds on the repository, not the connection's declared role. An invited developer could press "Merge pull request" — or merge up to ten clean pull requests in one press — on a `maintainer` connection, and the owner of a `developer` or never-chosen connection was refused a merge their upstream accepts. Both human entries now take the role the repository guard already resolved and pass it into the merge gate, so a developer is refused before any GitHub call with the sentence the card already carried, and an owner can merge from either connection. Automatic merging keeps reading the connection's role because the scheduler has no actor. The bulk control is drawn from the viewer's own permission and says so when it is withheld.
