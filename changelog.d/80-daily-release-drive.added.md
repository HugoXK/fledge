The daily minor release is now driven by a scheduled workflow instead of a habit: at 22:30 Asia/Shanghai it computes the 10+ merges / 5+ features rule from the API, writes the counts to the job summary, and either opens one mechanical `release: vX.Y.Z` pull request, enqueues the one already open, tags a merged release, or reports and stops. A mechanical release is recognised by its branch and title, not by the files it touches, so a pull request that happens to change the same five files keeps its full review.
