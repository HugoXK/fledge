Auto-merge now waits for the newest job on a pull request: a queued, running, failed, cancelled or paused follow-up holds the PR back instead of letting an older succeeded job merge it, so a merge can no longer land before the requested fix or after a failed run. The bulk merge reports such PRs in its skipped list together with the job state, and it no longer picks up a pull request that is already merged, so a repeated run reports and re-checks only the PRs it can still act on. Its operator message now names each skip reason separately, a job that has not succeeded apart from a failed check or a missing protection.
