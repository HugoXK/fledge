Stored encrypted secrets can now name the key that wrote them: a `v2` payload carries a key id, and the operator can supply named keys through `TOKEN_ENCRYPTION_KEYS_FILE` while `TOKEN_ENCRYPTION_KEY` keeps decrypting the existing `v1` values. A payload that names an id the process does not know fails closed instead of retrying with the default key, and a malformed or unreadable key file refuses to boot with the file and the offending id in the message. Nothing re-encrypts or rotates an existing value; the mechanism ships without a rotation action.
