A backup copy now records which key derivation produced it: the manifest's `encryption.kdf` and the `encryption=… kdf=…` line printed by `npm run db:backup` and the restore drill say `raw` for a 32-byte key or `scrypt` for a passphrase, so a restore knows what to supply without matching ids by hand. A base64-shaped key value that decodes to 16–31 bytes — a 32-byte key that lost its tail — is now refused with an exit naming the source and the byte count instead of silently being used as a passphrase. A key file readable by group or others still backs up but warns on stderr. Manifests written before the field existed keep validating.
