A ledger written before the head sha joined the `test_runs` key no longer refuses the first write after the upgrade. The old table is recognised by its own columns on open — `PRAGMA user_version` reads 48 on both shapes, so the version cannot tell them apart — and replaced from the same statement that creates the table on a fresh database, so the upgrade path and the fresh path cannot drift. The ledger is derived data that a later run repopulates, so nothing is copied row by row.
