An encrypted backup no longer writes the plaintext copy of the database into the backup directory. The copy is taken in an owner-only work directory outside it — `BACKUP_WORK_DIR` moves that area — and removed on every exit path, so a copy of the backup directory never holds a readable database, not even if a run is killed mid-encryption. `prune` and the next backup collect a stale plaintext leftover an older run left behind, while a file young enough to belong to a backup still running is left alone.
