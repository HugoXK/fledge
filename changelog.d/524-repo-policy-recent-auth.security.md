A repository settings save now needs a fresh GitHub confirmation, like the auto-merge toggle already did, when it changes the pre-merge policy: branch protection, the stage gate, the allowed and denied paths, the target branch or the repository role. A session that has not re-authenticated inside `RECENT_AUTH_MINUTES` is sent through the re-authorize bounce instead of writing, and a save that leaves that policy alone still goes through without asking. A policy change that passes the gate is audited once as `repo.policy` with the fields that moved.
