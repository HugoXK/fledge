The workflow comparator no longer reads a missing aggregate job as "nothing to check": a pull request that renames the in-run aggregate away from the accepted ids (`ci-ok-head`, `ci-ok`) is refused, naming the ids it looked for and the ids the head declares, a head that declares both is refused by both names, and the success line names the id it actually checked. The aggregate's `needs:`, base-evaluator and `path: base` checks follow whichever accepted id the head declares, so `#1273`'s rename is checked rather than skipped.
