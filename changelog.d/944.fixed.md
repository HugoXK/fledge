A deploy now copies every file of the release it is deploying, including one whose new content happens to have the same byte count and the same timestamp as the file it replaces. Before this, rsync's size-and-time check could leave that single file from the previous release in place while the rest of the tree was replaced, so the host could serve one old file beside a freshly built version: a file under `public/` was refused by the rollout gate's whole-tree comparison and rolled back, but a file outside it, such as `package.json` or a source file, was served unseen because the gate compares only `public/`.
