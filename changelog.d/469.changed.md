Error pages now say what the reply was and offer a way forward that fits the reader. The page prints the status the route already replied with (`404`, `403`, `500`, in the tab title too), and the action is chosen from the viewer: a signed-in person returns to the console, an anonymous visitor is sent to GitHub sign-in, and a route that has its own way out (the OAuth 403, a 5xx report form) keeps it. Server errors still never show a stack trace.
