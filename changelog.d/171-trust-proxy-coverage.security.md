A `TRUST_PROXY` whose entries together cover the whole IPv4 or IPv6 space is now refused at startup, the same way a `/0` range already was: host bits are masked, the entries are combined, and an IPv4-mapped prefix such as `::ffff:0:0/96` counts as the IPv4 range it actually trusts. An installation running such a list will not boot until the env names the proxy address or its narrow CIDR; a list that stops short of the whole space still starts. Separately, a request address that cannot be parsed - for example nine groups forwarded verbatim by a trusted hop - now falls into one shared rate-limit bucket instead of answering 500.
