The CodeQL gate now refuses a SARIF run whose `results` is present and is not a list — `null`, a number, a string or an object — instead of reading it as a clean analysis, crashing on it with a raw `TypeError`, or iterating a string into one finding per character. The refusal is named at the level that reads it, `run <n> results is not a list (found <shape>)`, and it is a refusal rather than a verdict: an empty `results` list and a run with no `results` key still pass as a zero-result analysis. The slot, no-run, malformed-JSON and missing-file refusals keep their wording.
