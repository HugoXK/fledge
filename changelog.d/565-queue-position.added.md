Queued jobs now show their position in the instance queue and the queue length (`#3/7`) together with the priority they compete on and the trigger that set it: by default a follow-up queues at 20, a manual run at 10 and any other trigger at 0, a run started from a work item carries that item's priority (which can come from its GitHub issue labels), and a retry keeps the priority of the job it retries. The job page lists the viewer's own queued jobs that are ahead, with each one's repository, priority and arrival, and states how many other accounts' queued jobs are ahead without naming any of them. The order is priority, then arrival — the same two keys the claimer uses — so equal jobs share a position, and the number is the order, not a promise that the job starts next.
