The measured clock offset is now used, not only reported. Above the same 120 seconds the alert rule fires on, `/readyz` answers 503 with `clock.state: "fail"`, `Jobs.enqueue` refuses with `CLOCK_SKEW` before any job row is written (counted as `fledge_admission_rejected_total{reason="clock_skew"}`), and the App JWT refuses with `CLOCK_SKEW_EXCEEDED` instead of signing from a stale correction. A reading is trusted for fifteen minutes, after which the clock is `unknown` and signing fails with `CLOCK_SKEW_UNVERIFIED`, so a GitHub outage can no longer keep a wrong correction alive. Stored timestamps are unchanged and a wrong host clock still needs the host fix.
