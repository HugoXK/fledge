Online database backups can now be encrypted with AES-256-GCM using `BACKUP_ENCRYPTION_KEY` or `BACKUP_ENCRYPTION_KEY_FILE`, with optional `BACKUP_ENCRYPTION_REQUIRED=true` for production; plaintext backups remain the default and existing copies restore unchanged. Encrypted copies use a `.db.enc` envelope carrying the format version, key id/version, salt, IV, authentication tag and ciphertext, while the manifest records only the ciphertext checksum and non-secret key id/version; the key id fingerprints the key a copy was encrypted with, so for a passphrase it is derived from the scrypt-stretched key rather than a fast hash of the passphrase, and a key source that is present but empty is refused instead of silently writing a plaintext copy. The restore drill detects `.db.enc`, decrypts with the configured key, and fails closed with a lost-key message when the key is missing or wrong; `docs/deploy.md` documents decryption, key custody, rotation and the lost-key failure.
