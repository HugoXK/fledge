Online database backups can now be encrypted with AES-256-GCM using `BACKUP_ENCRYPTION_KEY` or `BACKUP_ENCRYPTION_KEY_FILE`, with optional `BACKUP_ENCRYPTION_REQUIRED=true` for production; plaintext backups remain the default and existing copies restore unchanged. Encrypted copies use a `.db.enc` envelope carrying the format version, key id/version, salt, IV, authentication tag and ciphertext, while the manifest records only the ciphertext checksum and non-secret key id/version. The restore drill detects `.db.enc`, decrypts with the configured key, and fails closed with a lost-key message when the key is missing or wrong; `docs/deploy.md` documents decryption, key custody, rotation and the lost-key failure.
