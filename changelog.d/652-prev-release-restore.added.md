The restore checks now also restore a small fixture written by the previous release and migrated by the current build — `npm run db:prev-release:restore`, and the same check inside the test suite — so a column renamed or dropped without a migration fails on a fixture instead of on a real upgrade. A wrong or lost key reports `key-mismatch` and never passes, and `docs/deploy.md` records the fixture's provenance and the regeneration command.
