Both fixes are about the backup lock that keeps one run per `BACKUP_DIR`. A lock or takeover marker now names its holder's process start time beside the pid, so a lock left by a killed run whose pid the kernel has since reused is taken over instead of refusing every backup until that unrelated process exits; a lock written before the field existed keeps its old meaning and still refuses on a live pid. The takeover marker is also released only by the run that wrote it: a run that is stopped inside the takeover for longer than the grace, and resumes after another run has swept its marker and taken its own, no longer deletes that marker — so a third run can no longer create one and write beside a live holder.
