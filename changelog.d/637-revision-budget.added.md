A review that requests changes now starts a fix through a budget instead of without one: a third-party review bot can cause at most one fix per pull request, and the platform's own reviewer at most three per head (a repository can lower its own ceiling with the `repo:<id>:max_revisions` setting). A person's requests are never counted, a repeated request is still answered by the existing duplicate-fingerprint guard before any budget is spent, and every refusal writes one `trigger.revision_refused` audit row. The count resets when the pull request head moves, and a request that arrives while a review is already running keeps its author into the replay, so the fix it starts is counted exactly like one that started immediately.
