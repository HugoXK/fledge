`GITHUB_APP_WEBHOOK_SECRET` can now be rotated without a flag day: a previous value stays acceptable only until the ISO instant in `GITHUB_APP_WEBHOOK_SECRET_PREVIOUS_UNTIL`, `scripts/rotate-webhook-secret.mjs` rewrites the env file atomically at mode 0600 with the new value from stdin or an environment variable, a delivery signed with the retired value after its window is refused and audited as `app.webhook_secret_superseded`, and the diagnostics fields of `/healthz` name the active slot as `current`, `previous` or `none`. A previous value with no end now refuses to boot instead of accepting a retired secret forever.
