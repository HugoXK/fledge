`/metrics` now accepts its token only from `Authorization: Bearer <token>`, compared in constant time; the `?token=` form is refused, because a scrape URL ends up in proxy access logs, browser history and `Referer` headers. A production process refuses to start without `METRICS_TOKEN`, and refuses a `NOTIFY_WEBHOOK_URL` that is not an absolute `https:` URL, since that webhook carries the alert payload and its bearer secret. The loopback fallback for an empty token remains outside production only, and it is judged on the peer the trusted `TRUST_PROXY` hop saw, so a forged `X-Forwarded-For` cannot make a public request look local. Existing production deployments must set `METRICS_TOKEN` (for example `openssl rand -hex 32`) before upgrading; the direct-nginx install needs no `TRUST_PROXY` change.
