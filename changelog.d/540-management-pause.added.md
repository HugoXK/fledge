Pausing a job is a replay-safe command like cancelling: the pause form now carries the revision it rendered and an idempotency key, so a double submit returns the same receipt instead of pausing twice, and the paused job, its repository status, the audit row and the receipt commit together — a crash can no longer leave a paused job whose receipt still says the command was never applied. A command that is still unresolved now answers "这个操作还在处理中，请刷新页面查看结果。 / This action is still being processed; reload to see the result." instead of claiming the cancel failed. The rollout is staged behind `MANAGEMENT_SERVICE=off|shadow|on`, which defaults to `off` — the page people use today.
