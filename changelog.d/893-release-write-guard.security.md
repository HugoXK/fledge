Publishing a release, from the release form or from the readiness page's tag button, now needs a fresh GitHub confirmation and is paced by the destructive class limit like the other privileged writes, and its preflight refuses a target commit the default branch does not contain (a diverged or behind target, or a compare that cannot be read) instead of tagging it. A tag push runs the workflows committed in the tagged tree, so the ancestry check is what keeps "this release was built from this repository at this commit" checkable, and the version scan now compares a bounded number of the newest tags rather than one per tag.
