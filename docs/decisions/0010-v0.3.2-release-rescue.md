# 0010 — v0.3.2 release rescue (owner decision)

Status: **accepted** (2026-11-12)
Date: 2026-11-12
Decision owner: HugoXK

## Context

The normal mechanical release path could not produce a green pull request for
`v0.3.2`, for two independent reasons:

1. `test/readmeStatus.test.ts` requires each README status line to name the
   version in `package.json`. The mechanical release surface excludes the two
   READMEs, so the version bump alone leaves both status lines one release
   behind and `ci-ok` is red by construction (#348).
2. The nightly workflow now refuses to push a release branch when
   `RELEASE_OPEN_TOKEN` is not configured, because a branch no credential can
   open a pull request for is the orphan state #333 reports. That secret is not
   set in this repository.

An earlier orphan branch `release/v0.3.2` at
`224096bdadb3c2e683c4774dd8713f2dbc103fa6` existed with no pull request in any
state and no tag; it was deleted before the rescue so the slot was not wedged.

The owner chose a one-off rescue because `v0.3.2` carried the accumulated
fixes, the release branch was otherwise healthy, and #348 (the permanent fix)
was not yet landable.

## Decision

The owner authorized this exact rescue, and only this one:

1. Cut `release/v0.3.2` from `main` `4e8b7da7dce61fdaea9c2a0f4c242b3991a96f93`.
2. Run the mechanical release script for `0.3.2` (42 fragments) and update both
   README status lines to `v0.3.2` / `2026-11-12` by hand.
3. Open pull request #347. The README edit puts the tip outside the mechanical
   set, so the PR computes T3 and needs a PASS at the tip; this is the expected
   consequence of #348, not a policy change.
4. Run `npm run check` at the tip
   `4424f39edda815b61d2da4a859072af2992dab8e` (984 tests, lint, typecheck,
   build) and post the required PASS as `HugoXK-bot` at that exact tip. The
   owner authorized the reviewer credential to post that PASS; the review body
   records the commands that ran.
5. Enable auto-merge. The squash merge, the tag job and the release workflow
   are the only publish path; no direct push and no admin merge.

This is an explicit owner exception for `v0.3.2`. It is not a change to the
review policy, the risk tiers or the mechanical release rule.

## Consequences

- `v0.3.2` is published through the normal tag/release workflow; it is not a
  production deploy. The deployed version remains an owner action.
- #348 remains the permanent fix: the README status lines become part of the
  mechanical surface, with the decision recorded there. Until it lands, the next
  release has the same manual README step and must not be described as
  fully automated.
- The reviewer credential must not be used again to make a red mechanical
  release PR mergeable without a new owner decision recorded in a successor ADR.
- The audit trail for this exception is this ADR, PR #347 and the review body;
  no earlier record is edited.
