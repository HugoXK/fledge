## [Unreleased]

## [0.3.3] — 2026-11-13

### Added

- Fledge now ships `scripts/artifact-retention.mjs` and `npm run artifacts:prune`, an operator tool that reports and reclaims the workspace snapshots each agent run leaves under `FLYBOT_INSTANCE_ROOT`. It is a dry run unless `--apply` is passed, keeps the newest `ARTIFACT_RETENTION_KEEP` snapshots and anything younger than `ARTIFACT_RETENTION_MAX_AGE_DAYS`, never removes a workspace that `state.json` or `inflight.json` names, and prints the candidates' bytes, the total and an audit line on every run. `docs/deploy.md` carries the policy and a timer example.
- A per-job budget can now stop a job, not only alert after the spend. The repository setting `job_budget_action` adds `pause` and `cancel` to the default `alert`: at the job's next checkpoint, where the spend is already recorded and no extra model call is needed, a job over its budget is paused with its checkpoint kept or cancelled outright, and a late callback cannot revive it. The job page and the notification name the action, the observed cost and the next step, and an unknown cost is never treated as zero.
- A repository whose primary model is rate-limited or briefly unavailable now finishes the job on its next selected model instead of failing: the gateway retries only transient refusals, never an authorization failure, an exhausted provider quota or a policy refusal, and the job page and pull-request comment name the model that actually replied.
- A repository's Delivery section now shows a 7- and 30-day review trend: average review score, number of reviews, the changes-requested rate with its denominator, the median time from pull request to review and to merge, and the model each review ran. Windows with no review show `—` rather than zero, and a window with fewer than five reviews is labelled a small sample, so a single review is never read as a trend.
- Owner search at /search: one page over your own repositories, jobs, work items and audit entries, with repository, status, kind and date filters, 20 results per section and an empty state that says how to narrow.
- The evolution ledger can now hold versioned artifacts with lineage: a candidate declares the version it was built on and is refused if that base is stale, every accepted version records its parent and moves the `dev` pointer, a rollback moves the pointer back while leaving both versions readable, a repository can only accept its own artifacts, and a candidate that names the evaluator, authentication, the gateway, the merge gate or the CI configuration is refused before it is evaluated and the refusal is audited. Existing artifact rows keep their content, hash and status; a promoted row becomes the `stable` pointer.
- The console now follows the reader's system colour scheme: a light palette over the same token names is selected by `prefers-color-scheme: light` with no JavaScript, an explicit `data-theme="light"` or `data-theme="dark"` overrides it, and `color-scheme: light dark` makes form controls, scrollbars and the selection colour match the palette. Both palettes clear WCAG 2.1 AA for body, muted, badge, status and scrollbar pairs.
- Chinese headings now lift the Latin negative tracking to zero, take a slightly taller line-height, and are set in a Chinese-first font stack when the console is rendered in Chinese; heading sizes and the English rendering are unchanged.
- A multi-device visual matrix now boots Fledge with a throwaway database, captures the landing page before signing in, and renders the owner, account, repository, admin and workspace surfaces at nine widths in both languages. It fails on page or element overflow, on a `/settings` page missing the `#tokens` anchor its empty state links to, and on a section hidden under the sticky header, and uploads the screenshots as CI artifacts.

### Changed

- The five console states now show an inline SVG icon instead of a text glyph, so loading, empty, error, success and disabled share one geometry and one colour rule: `0` no longer reads as a count, `!` and `–` no longer depend on the reader's font, and `✓` no longer arrives from a fallback face at a different weight and baseline. Nothing about the wording, the role or the next action changes.
- Scheduled auto work is now backlog-driven: a repo with no open work item stays idle instead of starting a generic iterate job and producing an issue or PR on a timer. When work is open, the next session starts after the short work cooldown rather than the repository's legacy interval, and the scheduler records an idle status instead of inventing work.
- An idle repository can now run one low-frequency discovery session at its configured interval. The session may create at most one concrete issue and never a branch or PR; an empty result stays idle, so the team no longer invents work on a timer.
- Info tips are now real buttons that open on tap and keyboard focus, destructive actions use the shared confirmation dialog instead of the browser prompt, and the compact navigation keeps focus inside the open menu and restores it when the menu closes.
- The console reads more calmly and at a larger default size: one neutral page background and flat cards replace the layered gradients, a single accent carries interactive controls, table and meta text are larger, and the page padding scales with the viewport instead of jumping at a breakpoint.
- On a tablet, the job, admin-user and audit tables keep the identity, status and action columns visible and put the low-priority detail columns behind a "show all columns" control, so the row no longer needs a sideways drag to be understood.
- On a tablet, a table that is wider than its card now keeps the first column visible while the rest scrolls, shows a readable scrollbar gutter and a subtle edge shadow, and stops a sideways swipe from moving the page instead of the table.
- The console now fills the real visible viewport: the page and workspace use `dvh` with the previous `vh` fallback, the page respects the bottom safe-area inset, and the meta viewport opts into the notch area, so mobile browser chrome no longer hides the bottom of a page or the workspace frame.

### Fixed

- A pull request whose required `review-gate` check was green and whose earlier run of the same check had already used every automatic re-run could not merge, and the repair step answered "a new commit is needed" — the one remedy that throws away the review. The repair now repaints a spent run when the failing check it left behind completed at or before the newest verdict, waits instead of failing when that run is still running, and keeps the attempt cap for every other case.
- The CodeQL gate now refuses a SARIF whose `runs` slot holds no run — a `null`, an array, a string, a number or a boolean — instead of reading it as a clean analysis with zero results. A truncated or reshaped SARIF fails closed with `run <n> is not an object`, a real analysis that legitimately found nothing still passes, and the existing no-run, malformed-JSON and missing-file refusals keep their wording.
- The `main-health` reporter no longer creates the `ci:main-red` label on every run: the bootstrap moved to the issue-create path, so a green `main` performs no label write and a refused label create can no longer fail a run that had nothing to report. Every `gh` argument list and the write half now live in `scripts/lib/main-health.mjs` behind `apply(result, runner)`, so the suite pins the exact calls instead of only the decision that produces them.
- The SLO report now pins each of its six metrics to its own PromQL expression, so a queue wait can no longer print under job duration: the expressions and the fields they fill come from one list, and the suite fails if a value lands under the wrong label. A report that cannot read Prometheus still exits non-zero with the named error, now exercised by the tests instead of by hand.
- The nightly mechanical release pull request now updates both README status lines itself, so it no longer lands red against its own `readmeStatus` check. The version written there is read back from the `package.json` the release just bumped, and only the version token and the date change; any other README edit still needs its own review.
- A finished job no longer sends one email per run. Scheduled successes are carried by the daily summary, a failure that queued an automatic retry waits for the retry result, and failures for one repository are coalesced into one message per `JOB_EMAIL_COOLDOWN_MINUTES` (default 60). Settings gains an optional "email me when a scheduled job succeeds" switch, off by default, so existing users see no change; a run a person started — a manual run, or the retry/resume button — still mails its result. "Who started this run" is recorded on the job row when it is enqueued, because a scheduled repository's continuation is also a `followup` and the trigger alone cannot tell the two apart.
- A plan that nobody approves no longer blocks a repository forever: the scheduler reminds the owner two days before a configurable seven-day deadline and then closes the work item into the existing `closed` state with the new `closed_reason = plan_expired` and an audit row, instead of waiting indefinitely. The repository page names the deadline and the three ways out while the plan is pending, and a late approval is refused.
- The CodeQL gate now refuses a SARIF run whose `results` is present and is not a list — `null`, a number, a string or an object — instead of reading it as a clean analysis, crashing on it with a raw `TypeError`, or iterating a string into one finding per character. The refusal is named at the level that reads it, `run <n> results is not a list (found <shape>)`, and it is a refusal rather than a verdict: an empty `results` list and a run with no `results` key still pass as a zero-result analysis. The slot, no-run, malformed-JSON and missing-file refusals keep their wording.
- An English console opening a missing page — a stale link, an old bookmark, a typo, or an unknown locale under `/lang/` — showed an English title over the Chinese sentence `你访问的页面不存在。`, because the error page localized its title from the message table but had no entry for the sentence and passed it through unchanged. The sentence now has its English form, so the whole 404 block reads in the console's language, while the Chinese console keeps its Chinese sentence.
- A job that fell back to its second model and later answered on the primary no longer loses the fallback: the job page now states the fallback an earlier call made instead of silently naming only the last call's model, and it keeps the first fallback the job made even when a later call fell back again to another model. The pull-request automation comment still names only the last call's model and its attempts. A job that never fell back says nothing about one.
- The plan-expiry pass no longer tells a user that a plan was "已过期关闭" when the plan's work item had already reached `merged` or `closed` before the pass ran; the expiry is still recorded in the audit row and the `plan_expired:<job>` settings key, a terminal item is left untouched, and a plan whose item is still live still closes once with its one notification.
- The admin search page now pages its job and audit results twenty rows at a time, with links that keep the active filters and both sections' page numbers, so a result past the first page is reachable without editing the URL.
- The admin audit and job CSV exports stopped at 5000 rows without saying so, so a filtered export could read as complete while rows were missing. An export whose filter matches more than 5000 rows is now refused with the matched count and the cap, and the refusal is audited; a filter at exactly the cap still gets the whole file.
- Retention now reclaims the per-job `plan_expired:` and `plan_reminded:` settings rows, which the plan-expiry pass writes and no cleanup path used to delete. A database no longer grows by one marker per unapproved plan forever.
- Fledge now refuses to start when `PLAN_REMINDER_DAYS` is equal to or larger than `PLAN_EXPIRY_DAYS`, naming both values. That pair used to collapse the reminder window to zero and tell maintainers a plan was about to expire the moment it ended unapproved, with the deadline still days away.
- The page frame, header and footer now keep their content clear of a phone's home indicator and of the notch's side insets: each padding adds the matching `safe-area-inset` to the design value, so the clearance survives the 960px breakpoint instead of being dropped by a later shorthand, and a landscape notched phone no longer puts the first column under the sensor housing.
- The tablet column control now says which table it opens: every table that hides its low-priority columns carries an id and an accessible name, the button points at that table with `aria-controls`, and its label reads "Show all columns — Users" / "显示全部列（用户）". The three controls on `/admin` are no longer announced identically, and the breakpoint, the hidden columns and the no-JavaScript render are unchanged.
- A gateway call can only record its model and its cost on a job that the token's own user owns and that the token's `kind` marks as a job. A personal token named `job:<id>` is refused with `403 invalid_job_token` before the provider is called, so a name alone can no longer rewrite another user's job record.
- Console timestamps now carry an explicit `UTC` suffix, so `Last run`, job and audit times, and every other cell rendered by `humanTimeShort` say which clock they show; the instant itself does not move, the reader's own zone is still not applied, and the digest's `Asia/Shanghai` sentence is unchanged.
- A form control's only focus indicator was a box-shadow ring, and a forced-colours theme such as Windows High Contrast paints no shadow and forces the border colour to a system value, so a focused repository search, digest hour or any other `input`, `textarea` or `select` looked exactly like an unfocused one. Those controls now take a two-pixel outline in the system text colour when `forced-colors: active`, placed after the ring so it wins the cascade; ordinary colour modes still render the ring unchanged.
- The page frame keeps its padding in a browser without `env()` again: the safe-area declarations for `.wrap`, `.top-inner`, `.foot` and the header panel now sit inside `@supports (padding: env(safe-area-inset-top))`, so the plain pre-#489 shorthand outside it stays valid instead of collapsing to zero above 960px. The stylesheet harness learns `@supports` with a legacy view (the block dropped) and a modern view (the block applied), and both existing frames keep their pins against the modern view.
- Auto-merge now refuses a pull request whose linked work item is changes_requested, or whose newest succeeded review score is below AUTO_MERGE_MIN_REVIEW_SCORE (default 80). A manual maintainer merge can override the score gate, and the override is audited.
- A discovery session can no longer return a branch or pull request. The callback refuses it with DISCOVERY_PR_FORBIDDEN and audits the attempt; a discovery result with only an issue still creates one work item.
- Discovery now has a 60-minute minimum interval, so a repository with a 15- or 30-minute work cadence cannot turn into an issue generator. The discovery select starts at 60 minutes; work sessions keep the 15-minute cooldown.
- The main navigation now announces `aria-current="page"` only on the link whose own target is the page being shown. A nested route such as a job detail, a repository workspace or a settings sub-page keeps the section highlight and announces the generic `aria-current="true"` instead, so a screen-reader user no longer hears "current page" on a link to a different page while the document title names the one they are on.
- The work-item board now offers the `assigned → pr_ready` move, so a work item that still reads `assigned` when its job reports a pull request can be moved to the state the job service already writes. The state control had refused that step even though nothing else about the item changed.

### Security

- Personal `flg_` gateway tokens now carry a scope and a visible, finite expiry: the create form offers 30/90/365 days (default 90, `PAT_EXPIRY_DAYS`), the settings list shows the scope, the expiry date and the last-used time, and the gateway refuses an expired or revoked token with `401 invalid_api_key` and a token outside the `gateway` scope with `403 insufficient_scope`. Tokens minted before this change get one finite window from the upgrade instead of living forever, and only an admin can create an operator token without an expiry.
- Settings now lists the sessions you are signed in with, masks their addresses, and lets you revoke one or sign out every other session; revoking a row ends that cookie on its next request and is recorded in the audit log as `session.revoked`. The current session cannot be revoked by the row action - it is rotated instead, which issues a new cookie and deletes the old row.
- Repositories and FlyBot instances now have per-user ceilings: `LIMIT_REPOS_PER_USER` (default 10) and `LIMIT_INSTANCES_PER_USER` (default 3), plus an optional `LIMIT_INSTANCES_GLOBAL`. An add or provision beyond the ceiling is refused before anything is created, while a bulk selection that exactly fills the remaining slots is allowed and a repeated selection counts once — both repository-add paths consult the instance ceiling too, so adding repositories cannot leave a user with more running instances than the cap allows — with the stable codes `REPO_LIMIT` / `INSTANCE_LIMIT`, a localized message naming the ceiling that refused, and an audited `limit.refused` row; the repository page shows the usage line. Only an instance that occupies a slot counts, so a stopped instance does not block restarting it. Admins are exempt, removing a repository releases its slot, and lowering a ceiling never touches content that already exists.
- Destructive actions now ask for a fresh GitHub confirmation: deleting a repository, toggling auto-merge, changing a quota, creating or revoking an API token, approving or rejecting a user, and stopping a FlyBot instance are refused when the session has not re-authenticated within `RECENT_AUTH_MINUTES` (default 15). The refusal is audited as `recent_auth_required`, GitHub is asked to confirm the account again, and the form returns with its CSRF token intact so the action can be submitted once. Reads and normal job actions are unchanged. Those same actions are also rate-limited per client address (60 attempts a minute), so a resubmitting form or a stolen cookie cannot hammer one: a refusal is the route's own 429 from `@fastify/rate-limit` before anything is written or audited.


## [0.3.2] — 2026-11-12

### Added

- Every line a job writes now carries that job's id under one key, `trace`, instead of the three shapes (`job`, `jobId` and nothing) it used before; the bridge handoff, the mock runner and the gateway usage line carry it too. The job page prints the same value next to the timeline as the token to search, so one search returns the whole job and no other.
- The admin console now shows the state of the database backups it has been running: the newest copy with its size and age, whether that copy's manifest still matches the file on disk, how many copies exist, and a warning when the schedule looks stale. It is read-only — no backup, restore or delete control — and it reports a missing backup, a copy with no manifest, and a copy whose manifest no longer matches as separate rows, so a stopped schedule and a bad copy cannot be mistaken for each other. The restore drill leaves no recorded verdict yet, so the card says so instead of showing a result it cannot prove.
- A duplicate-work refusal now says which kind of duplicate it is: work still in flight (`DUPLICATE_WORK`, with the open pull request) or work that already landed (`ALREADY_FIXED`, with the merged pull request and its merge commit recorded in the audit detail and the event). Nothing else about dispatch changes: the preflight stays read-only and still creates no job.
- The dashboard now opens with a five-step first-run checklist — connect a repository, choose a role, add a model provider, start the instance, run the first job — computed from your own rows on every request rather than from a cookie. It shows one primary action at a time, names the reason a blocked step cannot be taken yet, and is replaced by a first-run summary linking the pull request once a job exists.
- The dashboard now opens with one next action instead of a wall of equally weighted cards: the question, alert, failed job or setup step that needs you, with the link that fixes it, and a quiet all-clear that names the next scheduled automatic run when nothing does. The summaries, repository table and recent jobs move into one collapsed disclosure, and no section is removed.
- The dashboard job list can now be narrowed by repository, status and kind. The filters live in the URL, so a refresh, a shared link and a pagination click all show the same list, an invalid value falls back to the unfiltered list instead of an error, and an empty result names the filters that produced it and clears them in one click.
- The repository page now opens as six sections — Overview, Delivery, Work, Team, Settings and Danger — behind a sticky subnav, so the actions a user takes sit one tap from the top instead of under a long scroll of configuration. The six sections regroup cards the page already showed; no data, form or validation changed, the three anchors the page published before (`#work`, `#delivery`, `#danger`) still open their section, and the inner anchors (`#inbox`, `#chief`, `#role`, `#board`, `#repo-settings`, `#connection`, `#jobs`) open the section that holds them. Without the tab script the page still renders every card, as it does today.
- A follow-up started by a "changes requested" review now carries the reviewer's own words from the review body into the goal the agent is given, on one `Reviewer asked:` line collapsed to a single paragraph of at most 1000 characters, ending in an ellipsis when it is clipped, and the job page shows that line back in the result card so a maintainer can see what the agent was told. Because the record and the parked request are now keyed by the reason together with that sentence rather than by the reason alone, two different reviews on one commit become two follow-ups instead of collapsing into one duplicate, and a second review that arrives while a job is running no longer overwrites the first in the pending queue.
- A review job now retries itself once, a minute later, when the failure was transient — the FlyBot bridge, the model, a timeout or a stalled worker — instead of waiting for the next 12-hour review slot. The retry keeps the same pull request and work item, is capped at one automatic attempt, and is skipped when the review already recorded a result, so a second COMMENT review is never posted blindly. Quota, credential, GitHub-side and review failures stay manual.
- The nightly release workflow now opens its mechanical `release/v<version>` pull request itself through the dedicated `RELEASE_OPEN_TOKEN` team secret, so a release no longer strands on a pushed branch; when that secret or another precondition is missing the run is red, pushes nothing and names the missing secret instead of reporting a blocked night.
- An approved account that never connects a repository now loses preview access by itself: an hourly sweep rejects it 7 days after registration, writes the `trial.expired` audit row the admin console already reads, and sends one bilingual notice naming the rule, the exemption for anyone who ever added a repository, and that an administrator can re-approve the account. The status change and the audit row commit together and the notice is sent afterwards, so the row is the record; the sweep is idempotent, never deletes an account or a repository, and can be run by an operator for one login or everyone, with `--dry-run`.
- Admins now get a read-only trial view at `/admin/trials` that lists every account, not only the ones without a repository. Before this, an operator had to open each account to guess whether a preview had lapsed, was about to lapse, or never applied. The page puts each account in one named state (running, expiring, eligible, expired, exempt as admin, exempt because a repository was used, or inactive), shows the time the sweep recorded an expiry, offers a state filter that survives a refresh, and writes nothing — no email address is shown and no button changes an account.
- A release now has one read-only status and one command to check it: `node scripts/verify-release.mjs --version X.Y.Z` reads the plan, release branch, pull request, annotated tag, image digest, SBOM, provenance attestation, GitHub Release and — with `--base-url` — the running `/healthz` back from the API and exits non-zero when any link is missing or disagrees. The same chain is rendered on `/admin` from the snapshot the command writes to `release-status.json`, the card links the recorded GitHub Release and compares the running build against the snapshot's tag target, and the publish workflow records the image reference, SBOM and attested digest in the release body so those links can be read back.
- An admin can now stop all platform work with one action: `POST /admin/platform/stop` persists the stop, refuses every new enqueue with `PLATFORM_PAUSED`, drains the active jobs (paused where a bridge can be reached, cancelled with a terminal reason otherwise, 25 per stop) and writes one audit row recording who stopped it, when and why. `POST /admin/platform/resume` clears the stop and reports which repositories the next tick will consider, without re-enqueueing the set the stop froze. A stop disables no repository, rotates no token and deletes no row, and the state is a persisted row so a restart cannot silently resume scheduling.
- The admin panel now shows a banner while the platform is stopped: who stopped it, when and why, with the resume action, in Chinese and English. It is read from the stop record on every request, so a reload no longer hides a stopped platform, and a stop whose record cannot be read is shown as stopped with the record named unreadable instead of a blank operator.
- Jobs now enter a durable queue when `QUEUE_DISPATCH=1`: the tick claims one job per repository with a lease, decrypts the job's short-lived callback and model-token secrets and dispatches it. With the flag off the inline path is unchanged. The job row records the lease and the encrypted dispatch secrets at schema version 33.
- Failed GitHub webhook deliveries are now visible in a superadmin-only `/admin/webhooks` page with event, action, repository, status, error, filters and pagination. A failed delivery can be retried explicitly from the console; the stored payload is replayed once, the action is audited and a processed delivery cannot be retried again. Raw payloads are not rendered in the table.

### Changed

- The refusal banner that stops a job because a pull request already covers the issue now links that pull request instead of printing its URL as dead text, for both the in-flight answer and the already-merged one, so a maintainer opens it straight from the banner. The link is built only for a github.com pull request URL; any other value stays escaped text.
- The console's cards, lists, tables and buttons now take one radius scale, one primary accent and one rectangle of spacing: the templates no longer carry layout in `style` attributes, the corners that sat one or two pixels apart are a named step, and only the blue accent colours a control while the brand green stays decorative, so a coloured panel no longer looks clickable.
- The required `review-gate` check now fails on a tip with an unresolved review thread, naming each `path:line` (an outdated thread reports its original line rather than `null`). It fails closed when the thread state cannot be read, so a green check now means the tip can actually enter the merge queue instead of only that the code compiles.
- Scheduled iteration now carries the previous runs and the open work items into the next job instead of starting from `repo.goal` alone. A due repo continues its oldest open work item (`followup`, or `review` when a PR and a maintainer reviewer exist) and only starts a fresh `iterate` when no work is open. The interval is now `max(interval, last duration * 1.5) + cooldown` with a failure backoff, and each run is classified as `pr`, `issue`, `review`, `zero` or `meta` so a "存量/盘点/清账" issue can no longer look like a productive run.
- The daily digest now puts the failed-task count in the email subject (`[失败 N]`) and a red banner at the top of the HTML, and marks failed or quota-exhausted job rows in red. A quiet day keeps the old subject.

### Fixed

- The remaining data tables now stack below 641px instead of hiding columns behind a scroller that a phone cannot show: each row becomes a card and every cell prints its column name, reusing the same mechanism the job table already used. The admin users and audit tables, the dashboard repository table, the repository page's delivery, board and work-item tables, and the support view's tables are covered, and the delivery board keeps its stage filter as a wrapping row of links rather than losing it with the header row.
- Test evidence is verified only when a test check actually ran and passed. A skipped or neutral test job, or a job whose name merely contains "test" (such as `latest-deps`), no longer reports the change as "Verified": the job page shows 未核实 / Unverified and the merge gate refuses a claimed green test that no test check supports.
- A job that never reached the FlyBot bridge now says so: the job page names the bridge as the failing component with the existing "Start or restart this repository instance, then retry" hint instead of "unknown failure", and the failure breakdown in `/admin/metrics` counts the job under `bridge`. The original transport error is kept inside the message, and the bridge URL is stored without its query or credentials.
- A pull request whose path guard was written but whose evidence was never verified no longer renders as Ready / 可合并. The console and the job page now require both halves of the merge evidence: a guard-only or evidence-only row reports Not verified and names the half that never ran, which is the shape a refused merge leaves behind.
- `npm run slo:report` refuses a `PROMETHEUS_URL` that carries a username or password, instead of letting Node print the credential in an error, takes credentials from the new `PROMETHEUS_AUTH_HEADER` variable, and only sends that header to a non-loopback host over `https:`.
- The work-item board no longer strands a row when a job ends without a pull request: a job refused for exhausted quota now returns its assigned or in-progress item to triaged, the same way a failed job does, and the recorded transitions offer that move back to triaged so the manual status endpoint and the board show it.
- A job that failed showed the sentence the backend wrote, which is Chinese, on an English console: on the job page, in the dashboard summary and inside the notification ("The job job_x failed: GitHub token 权限不足…"). A failure now carries a stable code and the sentence is built from it in the reader's language — credential, stall, lease, timeout, quota, budget, duplicate-work, stage-evidence, bridge and disabled-repository failures all read as one sentence in English or Chinese. A refused enqueue reads the same way, on every button that starts a job: a full queue, the per-user queue limit, the monthly repository budget, a revoked credential, a missing or malformed target branch, an already-running job, a disabled review role and a refusal to resume or cancel now say what stopped them in the reader's language instead of repeating the backend's Chinese. The raw text of a failure stays under Technical detail exactly as it was written, and the stored notification keeps it, so an operator keeps the original wording.
- The English console now shows redirect banners in English: the 63 route messages that only had a Chinese form gained an English entry or localizer in `src/i18n.ts`, and a test walks every `reply.redirect(...)` so a new banner without an English form fails `npm test`.
- A job whose model provider is over budget or rate limiting is now reported as a provider refusal instead of a 30-minute heartbeat stall. The bridge relays DSH's answer to the send, so the job page names the provider budget or limit, the owner is told to check the provider quota, and the failure is not retried as a transient stall. When the provider's answer never reaches Fledge, the stall sweep reads the instance state once, bounded, and reports a session that made no model call at all as its own failure rather than a generic stall.
- The dashboard's job filter and its 30-day window now survive each other: switching the window keeps the repository, status and kind you filtered to, the "Clear filters" links keep the window, and paging the repository table no longer resets the job list you were reading.
- The CodeQL gate now passes a valid analysis that found nothing instead of failing on an empty result list, and still fails closed with a distinct message when the SARIF is missing, unparseable or carries no analysis run.
- A job superseded as a duplicate is failed when the one-active-job invariant is restored on an older database, but the work item it was running used to stay `in_progress` forever, so the board showed work that could never move. The sweep now resets that item to `triaged` in the same transaction, and its audit row names the item id as well as the job id.
- The CodeQL gate now sees the class of result it exists to catch: `security-severity` is read whether the SARIF writes it as a number or a string, and rules that a query pack stores under `tool.extensions[].rules` are resolved by `ruleId` and `ruleIndex`. A security result whose severity cannot be read — and a result whose rule cannot be resolved — counts as high; a resolved quality query keeps its analysis level. The step also prints `parsed N result(s), H high/critical` beside every verdict and fails on an empty parse, so a blind gate can no longer look like a clean one.
- The gateway's two limiters now key on the same normalized client identity as every app-level limiter: an IPv6 client that rotates addresses inside its routed `/64` shares one 240/min bucket instead of minting a fresh bucket per address, and traffic from a different `/64` still gets its own bucket. The limits themselves are unchanged.
- The nightly secret scan is green again: the whole-history gitleaks run found one result that is not a secret — a synthetic fixture committed in the initial commit and removed from the tree by #185 — so it now carries a single `.gitleaksignore` fingerprint naming that commit, path, rule and line. The exception is commit-scoped rather than path-scoped, so a token pasted into the same file later is still a finding, and the full-history scan can be trusted as a signal instead of being permanently red.
- The footer and the `/admin` release card now report the same version `/healthz` serves. Both read `package.json` through one module-relative root instead of one of them using the process's working directory, so a process started outside the checkout — a systemd unit with its own `WorkingDirectory`, a container with a different root — can no longer report two versions of itself.
- Running jobs renew a five-minute lease every minute, and an expired lease is failed by the scheduler instead of waiting for the 90-minute job timeout. When the durable dispatcher is enabled, a new job is refused with `QUEUE_FULL` or `QUEUE_LIMIT` when the global or per-user queue cap is reached, and `/metrics` exposes queue depth, expired leases and admission rejections.
- The release workflow now names the SBOM image and artifact from the job-level release tag. A tag publish no longer stops at an empty image reference before creating the GitHub release.
- Fledge now enforces at most one queued or running job per repository with a partial unique index. Two concurrent enqueues for the same repository return `JOB_ACTIVE` for the loser instead of starting duplicate work. A database that already held two active rows for one repository is repaired when it opens — a running job wins, otherwise the oldest queued job, and the demoted rows are failed with `JOB_DUPLICATE_ACTIVE_SUPERSEDED` and one audit entry each — instead of stopping the process at startup.

### Security

- `GET /healthz` no longer names the deployed commit to unauthenticated callers. The liveness answer is unchanged — `200` with `ok`, `service`, `version` and `time` for everyone — but `commit` and `builtAt` are served only to a caller presenting the `METRICS_TOKEN` bearer (or a loopback caller in a development build with no token configured), the same rule `/metrics` uses. Without the credential the two keys are absent rather than `unknown`, so "not authorised" and "this build carries no stamp" stay distinguishable. The release verifier sends `METRICS_TOKEN` when it is set, so its running-commit comparison keeps working.
